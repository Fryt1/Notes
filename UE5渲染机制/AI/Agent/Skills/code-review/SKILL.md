# 代码审查 Skill

审查代码时，系统地检查以下方面：

## 1. 代码质量
- 命名规范：变量、函数、类名是否清晰易懂
- 代码结构：是否遵循单一职责原则
- 可读性：代码是否易于理解和维护
- 重复代码：是否有可以提取的重复逻辑

## 2. 性能优化
- 算法效率：时间和空间复杂度是否合理
- 资源使用：内存泄漏、不必要的计算
- 数据库查询：N+1 问题、索引使用
- 缓存机会：是否有可以缓存的数据

## 3. 安全性
- 输入验证：是否验证用户输入
- SQL 注入：是否使用参数化查询
- XSS 防护：是否正确转义输出
- 敏感信息：是否暴露密钥或凭证

## 4. 错误处理
- 异常捕获：是否正确处理错误
- 错误信息：是否提供有用的错误提示
- 边界情况：是否考虑极端情况

## 5. 测试覆盖
- 单元测试：关键逻辑是否有测试
- 边界测试：是否测试边界条件
- 测试质量：测试是否有意义

## 6. 文档和注释
- 函数文档：复杂函数是否有说明
- 注释质量：注释是否解释"为什么"而非"是什么"
- README：是否更新相关文档

## 输出格式

审查结果按优先级分类：

### 🔴 严重问题（必须修复）
- 安全漏洞
- 性能严重问题
- 功能性错误

### 🟡 建议改进（推荐修复）
- 代码质量问题
- 可维护性改进
- 最佳实践建议

### 🟢 可选优化（可以考虑）
- 代码风格调整
- 小的性能优化
- 文档补充
