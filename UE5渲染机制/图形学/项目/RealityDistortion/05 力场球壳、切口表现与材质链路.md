# 05 力场球壳、切口表现与材质链路

> 这一篇专门把两个最容易混在一起的话题拆开：
>
> 1. **力场球壳 visualizer 到底是什么，它和剔除逻辑是什么关系**
> 2. **当前切口视觉到底由哪些层构成，真正控制它们的是哪里**

如果这两个问题不先拆开，就很容易出现一种常见误解：

> “球壳材质都已经这么完整了，那它是不是就是剔除球本身？”

不是。

---

## 一、先说最关键的结论

当前大家口头上说的“剔除球材质”，按代码真实职责来看，更准确的名字其实是：

**force field visualizer 球壳材质。**

它负责的是：

- 把 field 的位置显示出来
- 把 field 的范围显示出来
- 给场景一个可见的能量球壳外观

它**不负责**：

- receiver 过滤
- 真正的几何剔除
- `HoleInfoTexture` 输出
- `Depth / Base / Shadow / VSM` 里的 `clip`

真正参与剔除逻辑的，还是 renderer 里那份 field 数据：

- `Center`
- `Radius`
- `Strength`
- `bEnabled`
- `ReceiverTagFilter`

所以最准确的理解应该是：

**球壳材质是剔除球的显示层，不是剔除逻辑本体。**

---

## 二、力场球壳这条链到底长什么样

当前 visualizer 最清楚的理解方式，不是从材质图看，而是从 C++ 组件链看。

```text
ADistortionFieldActor
  -> 挂一个 UDistortionFieldComponent
  -> 组件负责 field 数据 + visualizer 显示

UDistortionFieldComponent
  -> 默认兜底 Sphere mesh
  -> 运行时创建外层 / 内层两个 UStaticMeshComponent
  -> 为它们创建 MID
  -> 每帧写参数
  -> 由 UE 原生透明网格路径完成渲染
```

这条链和 `RealityDistortion` 自定义 mesh pass 是并行关系，不是同一条渲染路径。

---

## 三、为什么现在多了 `ADistortionFieldActor`

关键位置：

- `Source/RealityDistortion/Rendering/DistortionFieldActor.h`
- `Source/RealityDistortion/Rendering/DistortionFieldActor.cpp`

这个 actor 很轻，它做的事情其实只有一件：

- 默认创建一个 `UDistortionFieldComponent`
- 直接把它设成 `RootComponent`

它的意义不是新渲染功能，而是工程上的整理：

- 让关卡里能直接放一个 field actor
- 让参数在场景实例里更自然地暴露出来
- 让 force field 从“纯组件试验”更像一个正式功能对象

---

## 四、球壳几何到底是怎么来的

关键位置：

- `DistortionFieldComponent.cpp`

### 1. 默认 mesh 不是程序化体积，而是引擎内置球体

当前默认使用的是：

- `/Engine/BasicShapes/Sphere.Sphere`

所以这套 visualizer 从一开始就不是“自己写一个代理体积去光栅化”，而是：

**复用 UE 已经现成支持的静态网格球体。**

### 2. 真正进场景里的是两个运行时 `UStaticMeshComponent`

`UDistortionFieldComponent::EnsureVisualizerComponent()` 会运行时创建：

- `VisualizerComponent`：外层球壳
- `VisualizerInnerComponent`：内层球壳

它们会被统一配置成：

- `Movable`
- `NoCollision`
- 不投阴影
- 不参与导航
- 不进反射捕获
- 禁用 Nanite

也就是说，它们的目标非常明确：

**只做显示，不干扰主渲染逻辑。**

---

## 五、为什么要做双层球壳

当前 visualizer 默认支持：

- 外层壳
- 内层壳

它们不是重复画两遍同一个球，而是分工不同。

### 外层壳负责什么

- 主轮廓
- 主 rim
- 折射
- 流动和高光
- 玩家第一眼看到的主观感

### 内层壳负责什么

- 背面内腔
- 一点厚度感
- 把单层透明球的“玻璃片感”压下去

这套结构的目的不是做真实体积渲染，而是：

**用很轻的成本，把单层半透明球容易发假的问题压下去。**

---

## 六、当前 material 方案为什么强调“opt-in”

关键位置：

- `DistortionFieldComponent.cpp`
- `Tools/CreateDistortionFieldMaterial.py`
- `Tools/ClearDistortionVisualizerMaterialRefs.py`

当前这轮最重要的资源层变化之一，就是 visualizer 材质方案不再走“自动塞默认资产”的旧模式了。

### 现在的方向

- 组件默认只兜底 `VisualizerMesh`
- 对历史 managed legacy 材质引用，`EnsureVisualizerDefaults()` 会自动清理
- 脚本会生成新的 opt-in 材质资产
- 需要时手动赋给 `VisualizerMaterial` / `VisualizerInnerMaterial`

### 当前脚本生成的 4 张核心材质

- `M_DistortionFieldVisualizer_Inner_OptIn`
- `M_DistortionFieldVisualizer_Outer_OptIn`
- `M_DistortionFieldVisualizer_Inner_Formal_OptIn`
- `M_DistortionFieldVisualizer_Outer_Formal_OptIn`

而且脚本结尾已经明确写明：

> These assets are not auto-assigned. Assign them manually if needed.

这件事非常重要，因为它意味着现在的设计意图已经很清楚：

**资源生成和组件绑定，是两步，不再混在一起。**

---

## 七、运行时到底是谁在给材质喂参数

关键位置：

- `EnsureVisualizerMaterial()`
- `UpdateVisualizerMaterial()`
- `UpdateVisualizerComponent()`

### 1. `EnsureVisualizerMaterial()` 负责创建和绑定 MID

它会：

- 检查 source material 是否存在
- 在基础材质变了时重建 `UMaterialInstanceDynamic`
- 把 MID 绑到 mesh 的 0 号材质槽

### 2. `UpdateVisualizerComponent()` 负责几何 transform

它每帧会根据：

- `FieldRadius`
- `FieldCenterOffset`
- `VisualizerRadiusScale`
- `VisualizerInnerLayerScale`

计算：

- 外层半径
- 内层半径
- 世界位置
- 世界旋转
- 世界缩放
- 显隐

### 3. `UpdateVisualizerMaterial()` 负责每帧写参数

它会往 MID 写进去的核心参数包括：

- `Color / Tint / BaseColor`
- `TransmittanceColor`
- `EmissiveColor / GlowColor`
- `Opacity / Coverage`
- `RimStrength / CenterStrength`
- `Intensity / Glow`
- `Pulse`
- `ShellIndex`
- `FieldStrength`
- `FieldRadius`
- `Time`

这说明 visualizer 材质和 C++ 的分工已经很清楚：

- C++ 负责把当前 field 状态翻译成参数
- 材质负责把这些参数解释成最终球壳视觉

---

## 八、当前 visualizer 还有两个必须说清的现状

### 1. 动画参数口已经留了，但运行时还没真正打开

虽然材质图里已经给 `Pulse` 和 `Time` 留了入口，
但当前 `UpdateVisualizerMaterial()` 实际写进去的还是：

- `Pulse = 1.0`
- `Time = 0.0`

所以现在的实际状态是：

**材质有“可动”的能力，但 C++ 当前喂的是静态值。**

### 2. visualizer 更像正式功能了，但还处在资源收尾期

你现在已经有：

- actor 包装
- 双层球壳
- opt-in 材质
- legacy 清理脚本

但资源层还没有彻底收完，所以当前最好把它理解成：

**系统结构已经明确，资源层还在做最后整理。**

---

## 九、当前切口视觉到底由哪些层构成

这部分不能再用“球壳材质”来理解了。

真正控制主视图裂隙视觉的核心位置，是：

- `Engine/Shaders/Private/RealityDistortionComposite.usf`

当前这版最值得记住的 5 层结构是：

### 1. 边界切口层

它负责：

- 裂隙切到哪里
- 边缘带宽
- ridge 和边缘连贯性

也就是：

**先把“切开”这件事立起来。**

### 2. 主 pulse 层

它负责：

- 主要节奏
- 中心到边缘推进的能量环
- “这个裂隙正在活动” 的第一阅读点

### 3. 次 pulse 层

它负责：

- 给主 pulse 之外再补一层次级节奏
- 避免动态结构只有一圈
- 把内部 rhythm 做得更完整

### 4. 折射 + 厚度吸收层

它负责：

- 背景被轻微扭曲
- 洞内部不是完全平透
- 更厚的地方更吃光

这一层最关键的价值，是把效果从“贴片”往“空间层”推进。

### 5. 内部 ribbon / wisp 层

它负责：

- 内部不只是空的
- 有一点能量流向
- 内部结构不只是 ring

这一层是加分层，不是主角，但没有它内部会非常空。

---

## 十、为什么当前效果已经不像最早那样“只有一层蓝面”

因为现在的 composite 已经不是“简单 tint + 一点折射”了。

当前版本里，真正站住主次关系的是：

- 边界层先立轮廓
- 双 pulse 负责节奏
- transmission / thickness 负责空间感
- ribbon / wisp 负责内部层次

所以你现在再看这版裂隙，会明显感觉到它已经不是早期那种：

- 一层蓝底
- 一圈发光边
- 一点后期 distort

而是开始具备“空间切口”的复合结构了。

---

## 十一、为什么这套球壳不需要自定义 pass

### 问题：既然主系统都改到 renderer 里了，为什么球壳 visualizer 不继续走自定义 pass？

**回答：**

因为它的职责不同。

visualizer 球壳只负责：

- 把 field 显示出来
- 提供一个场景里可见的能量壳层

它不需要：

- 参与 receiver 过滤
- 写 `HoleInfoTexture`
- 写 stencil
- 影响 `Depth / Base / Shadow / VSM`

所以对于它来说，直接复用 UE 原生的透明静态网格渲染链路，反而是最合理、最轻的方案。

---

## 十二、自问自答：最容易混淆的 4 个问题

### 问题 1：球壳材质是不是就是“剔除球材质”？

**回答：**

不是。

更准确地说，它是“剔除球范围的可视化球壳材质”。

真正剔除逻辑仍然在 renderer 的 field + receiver + clip 这条链里。

### 问题 2：为什么 visualizer 做得再好，也不能替代真正的挖洞？

**回答：**

因为它只是在场景里画了一个透明球壳，并没有改变 receiver 的深度、可见性和阴影关系。

### 问题 3：为什么当前切口视觉主要看 `Composite`，而不是看 receiver 材质？

**回答：**

因为当前最终裂隙视觉主要来自 `HoleInfoTexture + SceneColorInputTexture + SceneDepth` 的全屏合成。

receiver 材质更多是在参与提交资格和基础链路，而不是直接决定最后的裂隙外观。

### 问题 4：为什么效果还是偶尔有空壳感？

**回答：**

因为现在已经有“边界、节奏、折射、内部层次”，但还没有真正的 `interior / cap pass`。

也就是说，现在有“切开后的视觉”，但还没有“切开后真实存在的内部表面”。

---

## 结论

这一篇最核心的结论可以压成两句：

1. **visualizer 球壳是 field 的显示层，不是剔除逻辑本体。**
2. **当前主视图裂隙视觉的主控制点在 `RealityDistortionComposite.usf`，而不是球壳材质本身。**

把这两件事分清之后，后面无论你是继续改 visualizer，还是继续做 `interior / cap`，方向都会清楚很多。

## 补记：2026-03-16 Composite 表现收束的真实改动

这次 `RealityDistortionComposite.usf` 的修改，不是在推翻现有结构，而是在现有结构里做一次很明确的“风格收束”。

### 1. 目标不是把波纹抹平，而是把崎岖感收住

这次不是不要破碎感，而是不要那种一眼看上去太乱、太尖、太抖的破碎感。

所以对应处理是：

- 收 `FlowWarp` 的幅度
- 收 `DynamicRibbon` 和 `InternalWisp`
- 保留一点边缘起伏和内部扰动
- 但不再让大块形变主导整个切口

### 2. “油”和“太透”本质上来自折射与透射占比太高

之前那种“有点油”“像只是透过去”的感觉，根因不是单一颜色问题，而是这些项一起叠出来的：

- refraction 太强
- chromatic offset 太明显
- transmission 太依赖 `SceneColorInputTexture`
- surface presence 不够稳

所以这次对应做的是：

- 降 `RefractionStrength`
- 降 chromatic offset
- 降 transmission 的混合权重
- 提高 `SurfaceBody`、`SurfaceBaseMix`、`SurfacePresence`

这一步的目标不是把洞做成实心，而是：

**让切口看起来像有一层表面，而不是只是在看被扭曲的背景。**

### 3. “突然没了”不是亮度问题，而是周期切换问题

这次最重要的认知之一，就是把这件事说清楚了：

- 看起来像“波纹突然消失”
- 但更底层其实是 pulse 的相位 reset
- 相位一 reset，环心就会从外圈硬跳回内圈

所以只补 glow、补边界 carry，其实都不够。

最后稳定下来的办法，是三层一起做：

- ring 加 trail
- 边界加 carry / residue / continuity
- current / prev / next 周期短暂重叠

这才真正把“突然断”和“突然跳”压了下去。

### 4. 当前 composite 的边界已经很清楚了

到现在这个阶段，可以很明确地说：

- 这套 composite 已经能比较稳定地塑造切口轮廓、节奏和空间感
- 它也已经能把“太乱、太油、太跳”这种直接破坏观感的问题收掉
- 但它本质上仍然是屏幕空间风格化切口，不是真正的内壁 / 切面几何

也就是说，后面如果还要再往“更像真实空间裂口”走，关键就不在继续堆花纹，而是在 `interior / cap` 这条链上补真实内部表面。
