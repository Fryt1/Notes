# RICH 投资平台

这是一个把个人投资管理、市场数据、量化策略运行与因子研究放在同一套 Web 平台中的项目。本文只根据当前实现整理；旧项目文档、产品路线图和 README 不作为事实依据。涉及“能否稳定运行、实盘是否可用、策略是否有效”的问题，仍需分别做环境验证与实盘风控，不能从目录结构直接推断。

## 平台要解决什么

- 管理个人资产：持仓、交易、现金账户、资产组与组合视图。
- 做投资辅助：定投计划、组合/投资分析、计算器、市场图表与通知。
- 做量化研究与运行：策略管理、历史回测、数据管理，以及策略运行记录与日志。
- 做因子研究：数据集、因子库、构造与评估运行、归档和准入工作台。

它更像一个“投资工作台”，而不是只做某一种市场、只做回测，或直接承诺自动盈利的交易机器人。

## 量化部分如何衔接

策略通过统一的 `StrategyProtocol` 接入运行时。运行时向策略提供上下文、数据、Broker 和组合状态；策略按 bar 产生订单，运行时再处理成交、更新持仓并记录结果。

```text
策略代码
   → 策略运行时与指标
   → 数据 / Broker / 组合 三个端口
   → 回测适配器 | Paper 适配器 | Live 适配器
   → 运行记录、日志、回测结果与前端展示
```

这表示三种运行模式在接口层面被统一了，但不等于它们在数据延迟、成交规则、费用、限频和异常处理上天然等价。当前实现里，Paper 使用 Binance 数据适配器与独立的模拟成交账本；Live 的 Binance 适配器另有下单开关、单笔名义金额/数量上限、熔断与交易时段等配置。A 股 live adapter 目前是明确的 stub（占位），不能当作已完成的实盘接入。

## 因子研究在平台中的位置

因子研究不是一个脱离回测的脚本目录，而是作为后端插件和前端独立页面挂入平台。当前 UI 路径覆盖：

- 因子构造：公式、pipeline、GP、AlphaGen、ML；
- 研究数据与辅助库；
- 运行与任务；
- 因子归档、版本/证据查看与准入工作台。

后续要重点确认的不是“能生成多少因子”，而是数据时点、训练/验证切分、筛选与晋升门槛，以及最终信号如何接入组合构建、回测和 Paper/Live。那些是研究可信度的核心链路，需要单独写模块文档并按代码与实验记录核对。

## 安全边界

不要在 Vault 中保存账户密码、API Key、API Secret、私钥、交易所导出文件或其他凭据。实盘配置应使用环境变量或凭据管理机制；在没有完成独立风控、权限和小额验证前，不把回测或 Paper 结果视为实盘授权。
